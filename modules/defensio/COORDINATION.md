# Defensio — parallel session coordination
Defensio (denial management) is bootstrapped by amendment 36 in one session; parallel feature sessions start at A37. Each session has a TAG (the amendment number it is applying, e.g. A38).

## Ownership (who may write where)
- Defensio owns the `denials` entity from amendment 36 on — `data/repositories/denials.js`, `data/seed/denials.js` (the payer-code catalogue and the intents), `data/engines/denial-router.js`, `data/engines/denial-resolution.js` and `data/seed/root-causes.js`. Taken over from Claima (A31, revoked in A36 — logged in modules/claima/COORDINATION.md); Claima keeps *posting* denials from `data/repositories/remittances.js` through `denials.create`, which is the A29 contract and does not change. The files stay in `data/` — a repository never moves into a module.
- Defensio owns two stubs a later amendment fills, each a table with `create` and reads only, a TODO header naming the taker: `appealCases` (`data/repositories/appeal-cases.js`, A38 / F3 — Appeal Management) and `tpaFeeAccruals` (`data/repositories/tpa-fee-accruals.js`, A42 / F7 — TPA fee reconciliation). Extend them in place; do not rename the ids (`AC-0001`, `TPA-0001`) the denials seed already writes.
- `handoffs` (`data/repositories/handoffs.js`) stays Pactum's until the Defensio feature that works underpayments takes it — Pactum's manifest and the file's own header already name Defensio as the taker; the `DefensioHandoff` route (labelled "Contract hand-off") writes to it today.
- Each session writes ONLY inside modules/defensio/features/<its-feature>/ and its own data/seed/<entity>.js + data/repositories/<entity>.js listed in its amendment.
- SHARED files (append-only, one-line edits, never rewrite): modules/defensio/module.js (add your nav entry + routes inside the block marked with your TAG), shared/config.js (add keys under CONFIG.defensio, never edit others'), CLAUDE.md (append your ### entry only), data/store.js (register your entity line only), this file.
- Never edit another session's feature folder or entity files. If you need something changed there, write a request in the Requests section below and stop that part of your work until it is answered.
- data/repositories/denials.js is shared: add helpers in a section headed by your TAG; never modify an existing helper's signature or behaviour.

## Contract (interfaces every session may rely on)
- The denials repository helpers published below, plus everything Claima publishes in modules/claima/COORDINATION.md (claims, remittances, write-offs, coding, charges, batches, lifecycle) and Frontis's pre-auth register (`data/repositories/preauth-requests.js`).
- Cross-feature links go through denial ids, claim numbers, appeal-case ids, accrual ids — never by importing another feature's files. A module never imports another module's files: Claima's chip helpers are copied into modules/defensio/features/denials/denial-chips.js, not imported.
- All dates ISO YYYY-MM-DD; ids not labels; every screen uses ctx.onData; pickers use findActive() helpers.
- Expected amounts are never recomputed here: a denial's evidence reads the claim line's stamped `payerShare` / `allowedExpected` (Claima's assembly stamp) and nothing else.
- Every triage, route, reclassification and resolution is audited under entity `denials`, entityId = the denial id — the same `audit` pattern Claima uses.

## Protocol
1. On start: read this file fully, append "TAG started <time>" under Status.
2. Before editing any SHARED file: re-read it from disk, make the one-line/one-block change under your TAG, save immediately. Never hold a shared file open across other work.
3. When you add a helper others may use: list it under "Published helpers" with its signature and one-line semantics.
4. When you need something from another feature: write it under "Requests" as "TAG → TAG: need <helper/field>, signature <…>"; poll this file every few minutes; the owner answers under the request and implements it in their own files.
5. If you find a conflict, a broken import, or a failing selfCheck caused by another session: write it under "Conflicts" with file + line; do not fix files you don't own.
6. On finish: run node --check on the whole tree and load every Defensio route, then append "TAG done <time>, routes: …" under Status. The last session to finish runs the full-tree check once more.

A36 — `data/repositories/denials.js` (every A29 and A31 helper listed in modules/claima/COORDINATION.md is kept unchanged in signature; what follows is new or widened).
- Shape additions: `denial.category` (CATEGORIES: Clinical | Technical | Administrative), `denial.tier` (TIERS: Hard | Soft | Underpayment), `denial.separation` (SEPARATIONS: True | Contractual | TPA; null until triaged), `denial.reclassification` (`{ kind: 'Contractual' | 'TPA', ref ('RN-<denial id>' | 'TPA-0001'), claimNo, amount, note, at, by }` | null), `amounts.reclassified`, status `Reclassified` (resolved). Identity, asserted by `selfCheck()` and by `denial-resolution.js` on load: denied = recovered + lost + writtenOff + reclassified + transferred + open.
- `triage(id, { class, rootCauseId, note, category, tier, separation = 'True', assignee })` → the row or `{ error }`: a separation other than True hands off to `reclassify`; a true denial needs a class and a root cause and takes category and tier off the root cause when not given; `assignee` (a name, 'me' or null) is applied when the key is present. `triageMany(ids, { class, rootCauseId, note, route?, category?, tier? })` → `{ done[], problems[] }`.
- `reclassify(id, 'Contractual' | 'TPA', { note (required), category, tier, assignee })` → the row Reclassified or `{ error }`: open → `amounts.reclassified`, active route ended; Contractual writes a `Reconciliation note` audit entry on the claim (`claims` / claim id, ref `RN-<denial id>`), TPA creates a `tpaFeeAccruals` row; `resolution.kind` is 'Contractual' or 'TPAFee'.
- `route(id, 'Appeal', …)` → creates an `appealCases` row (ref `AC-…`) with the denial's appeal-by date; `linkOf` points it at `#/defensio/appeals/<id>` (A38's route — the shell sends it to the Defensio home until then). `ROUTES` is now `Recode, ChargeCorrection, AuthRework, Refresh, Appeal, DefensioHandoff, PayerReconsideration, WriteOff`; `DefensioHandoff` reads "Contract hand-off" (Pactum's underpayment register). - `resolveFromAppeal(appealId | denialId, 'Won' | 'Lost' | 'Settled', { amount, at, by })` → the row — what A38 calls when a case ends (Won recovers what is open, Lost loses it, Settled recovers `amount` and chains the rest).
